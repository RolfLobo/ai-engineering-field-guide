## What the section says

The webinars are the narrative, spoken-word layer of the same research: what the role is, what the data says companies hire for, how interviews run, how take-homes are graded, and how to pick a portfolio project. Their unique value over the written sections is the Q&A - dozens of career questions answered with the same data-driven posture, including positions you won't find elsewhere in the repo.

## Files covered

- [webinars/README.md](../../webinars/README.md) - series index with dates and recording status
- [webinars/01-a-day-of-ai-engineer.md](../../webinars/01-a-day-of-ai-engineer.md) - Feb 16, 2026. The practical reality of the role. Q&A gems: n8n-style clickers are not engineers ("without engineering rigor, best practices, and tests"); traditional NLP is mostly legacy now (cheap gpt-4o-mini), except spellcheckers and sub-millisecond search; coding agents are "enthusiastic interns" - sometimes sneaky (the Claude Code test-deletion anecdote), so engineers stay necessary; startups should hire generalists first, specialists later; evaluation tooling: "the best tool is the one you write yourself," start in Excel, then pandas, then CI/CD
- [webinars/02-defining-the-role.md](../../webinars/02-defining-the-role.md) - Feb 24, 2026. The 895-job-description analysis (Jan 2026, five cities) that became the role section: 70% AI-First, RAG the #1 named pattern, 93% need beyond-GenAI skills, Python 82.5%, fine-tuning niche. Q&A: an AI engineer is a software engineer specialized in AI (3-4 months to cross over); hiring managers spend 5-10 minutes on a resume and read the README first - write it for two audiences (peer reviewer and time-starved HM); tutorial-copied projects are worthless, original problem-driven projects are enormous value; TDD is essentially never in JDs (0.4%) but quality outcomes (CI/CD, monitoring, evaluation) are in 73%; build 5-6 small focused projects rather than one large one; local models are a real future because current API prices are subsidized
- [webinars/03-the-interview-process.md](../../webinars/03-the-interview-process.md) - Mar 3, 2026. The seven-step interview structure, two coding-round types, deep-dive dynamics, AI vs ML vs traditional system design, STAR behavioral prep. Q&A: deploy even a small project with monitoring on two users; observability (Pydantic AI + Logfire) is "an API key and two lines of code" - no excuse; testing + evaluation + observability are what set juniors apart; RAG is a prerequisite for agents, and many problems need no agent at all; interview failures: look for systematic patterns across 3-4 interviews, use ChatGPT as a teacher not a solution provider
- [webinars/04-take-home-assignments.md](../../webinars/04-take-home-assignments.md) - Mar 9, 2026. The take-home analysis later written up as [interview/questions/06](../../interview/questions/06-home-assignments.md): what companies ask (RAG 40%+, agents 30%+), formats, rubrics, and what makes submissions stand out (eval-first is the top YC-startup signal). Adjacent Q&A: no CS degree required; senior DS should bring engineering up to baseline and lead with evaluation
- [webinars/05-selecting-a-portfolio-project.md](../../webinars/05-selecting-a-portfolio-project.md) - Jun 29, 2026 workshop at AI Shipping Labs; the spoken version of the [portfolio method](portfolio.md): the six-step selection framework, turning research into a scoped first version, and the six-point README checklist. ## Key claims

- The webinar Q&As take positions the data files don't: on no-code AI (not engineering), on traditional NLP (mostly legacy), on data science's future (generalists fine, notebook-only struggling), on local models (subsidized API pricing can't last)
- The hiring-manager perspective (5-10 minutes, README first, checkboxes: real problem, clear description, tests/eval/CI/CD) is stated most concretely in webinar 2

## What is actionable

- Read webinar 2's Q&A before polishing any portfolio README
- Webinar 3's Q&A is the fastest preparation shortcut for career changers planning interviews
